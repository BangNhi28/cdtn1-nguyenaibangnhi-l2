Track: Công nghệ phần mềm (SE)
Luồng: L2 - Tiếp nhận và phân loại yêu cầu bảo hành


## 1. Mục tiêu
 Xây dựng tài liệu phân tích và thiết kế cho hệ thống **SMART CRM – Mekong Mobile**, tập trung vào luồng **tiếp nhận và xử lý yêu cầu bảo hành**.

Mục tiêu của BT1:
- Mô tả yêu cầu nghiệp vụ và yêu cầu chức năng của hệ thống.
- Xác định các tác nhân và Use Case chính.
- Thiết kế kiến trúc phân lớp cho hệ thống.
- Thiết kế mô hình dữ liệu và sơ đồ ERD.
- Thiết kế wireframe cho các màn hình chính.
- Đảm bảo các yêu cầu có khả năng truy vết từ SRS → Use Case → Kiến trúc → Mô hình dữ liệu → Wireframe.

Phạm vi chính gồm:
- Tra cứu khách hàng.
- Tạo yêu cầu bảo hành.
- Phân loại nhóm sự cố.
- Xác định mức ưu tiên.
- Theo dõi hạn cam kết (SLA).
- Theo dõi trạng thái và lịch sử xử lý yêu cầu bảo hành.

## 2. Yêu cầu môi trường
Môi trường và công cụ sử dụng:

- **Git / GitHub**: quản lý mã nguồn và tài liệu.
- **draw.io (diagrams.net)**: thiết kế Use Case, Architecture, ERD
- **Figma / Stich** : vẽ thiết kế wireframe
- **Markdown**: viết README và tài liệu SRS.
- **Microsoft Word / PDF**: biên soạn và xuất bài BT1.
- **Trình duyệt web**: dùng để truy cập GitHub và diagrams.net.
